# EtherCAT 직접 제어 검증 계획

실제 장비에 적용하기 전에 아래 6단계를 순서대로 통과시킨다. 각 단계는 **목적 → 시험 항목 → 통과 기준 → 기록할 것** 으로 구성한다.
앞 단계가 실패하면 뒤 단계로 넘어가지 않는다.

| 단계 | 대상 | 소요 | 하드웨어 |
|---|---|---|---|
| 0 | 소프트웨어 단독 (시뮬레이션·단위 시험) | 1일 | 없음 |
| 1 | 벤치: 드라이브 1대, 모터 무부하 | 1~2일 | 개발 PC + AZD-CED 1 + 모터 |
| 2 | 벤치: 다축 + IO | 2~3일 | 드라이브 3대 이상 + EK1100/EL1889/EL2889 |
| 3 | 장기 안정성 | 72시간 이상 | 2단계 구성 그대로 |
| 4 | 고장 주입 | 1~2일 | 2단계 구성 |
| 5 | 배포 환경 (Linux 미니PC) | 2~3일 + 72시간 | 미니PC |

---

## 0단계 · 소프트웨어 단독

**목적**: 하드웨어 없이 상태기계·단위 변환·인터록 논리의 결함을 걸러낸다.

| 항목 | 방법 | 통과 기준 |
|---|---|---|
| CiA402 상태기계 | 시뮬레이션에서 서보 온/오프, 이동, 정지, 급정지, 알람 리셋, 원점복귀 반복 (GUI 스모크 스크립트) | 상태 전이가 규격 순서를 따르고 예외·크래시 없음 |
| set-point 핸드셰이크 | 이동 중 새 이동 명령 연속 10회 | 각 명령이 ack 후 실행, "set-point not acknowledged" 없음 |
| 단위 변환 | 리드 10000/5000/2500 µm 로 µm↔step 왕복 | 반올림 오차 1 step 이하, API 응답 step 값이 계산과 일치 |
| 인터록 | 입력 강제로 EStop/Door/AreaSensor 각각 on/off | 상승 에지에서만 동작, 활성 중 이동·서보온 409, 해제 후 정상 |
| 축 조건 인터록 · 이동 중 | 규칙 "X 이동 중 → Y Halt+차단": X 절대 이동 중 Y 이동 시도 → X 정지 후 재시도 | X 이동 중 Y 거부(사유 표시), X 정지 뒤 1~2사이클 내 Y 허용, 트리거 1회 |
| 축 조건 인터록 · 위치 범위(허용) | 규칙 "Z 1000~2000 µm 안일 때만 X": Z=0 → Z=1500 → X 이동 중 Z=3000 | 시작 시 X 차단, Z 진입 후 X 허용, Z 이탈 순간 X Halt+차단(트리거 2회) |
| 축 조건 인터록 · 히스테리시스 | 위 규칙 h=50: Z 2040 → 1990 → 1940 / Block 규칙 5000~6000 h=50: 5500 → 6030 → 6060 | 2040·1990 차단 유지, 1940 해제 / 5500·6030 차단, 6060 해제 (진입은 경계 즉시) |
| 축 조건 인터록 · 검증 | 자기 참조(소스=대상), Min≥Max, 2h≥폭, 이름 중복, 없는 축 | 규칙은 목록에 남고 오류 표시·비활성, 편집기는 저장 비활성 |
| 인터록 편집기 | GUI 추가 → 즉시 동작 확인 → 편집(통계 이월) → 삭제(확인 창) → 재실행 | devices.json 반영, 제거된 규칙의 램프 OFF, 순서 유지 |
| 상태 출력 | AnyMoving/AnyFault/AnyInterlock/Heartbeat 비트 관찰 | 조건과 1사이클 내 일치, 하트비트 1 Hz |
| 별칭 | 축·비트 별칭으로 API 호출, 중복 별칭 | 번호와 동일 결과, 중복은 409 |
| 설정 파일 | devices.json/appsettings 잘못된 규칙(없는 모듈·비트) | 시작 시 오류 로그, 해당 규칙만 비활성, 나머지 정상 |

기록: 스모크 스크립트 출력, 캡처 화면. **권장 추가 작업**: Axis 상태기계와 IoBits 를 xUnit 단위 시험으로 고정해 회귀를 자동 검출한다.

## 1단계 · 벤치, 드라이브 1대 (모터 무부하)

**목적**: 실제 드라이브와의 통신·PDO·파라미터 해석이 맞는지 확인한다. 주전원 없이 24 V 제어전원만으로 시작한다.

| 순서 | 항목 | 통과 기준 |
|---|---|---|
| 1-1 | 연결·OP 전환 | 슬레이브 표 `OP`, WKC = 기대값, 로그에 `All slaves OPERATIONAL` |
| 1-2 | PDO 재매핑 | 로그에 SDO 오류 없음, `IOmap uses 40 bytes` 근처. 실패 시 덤프된 기본 매핑으로 구조체 수정 |
| 1-3 | 드라이브 값 읽기 | 로그의 분해능·기어비·속도/가감속이 MEXE02 설정과 일치 |
| 1-4 | 상태 워드 해석 | 서보 오프 상태에서 `SwitchOnDisabled/ReadyToSwitchOn`, 비트 표시가 드라이브 LED·MEXE02 와 일치 |
| 1-5 | 서보 온 (주전원 투입 후) | `OperationEnabled`, 모터 여자음, 알람 없음 |
| 1-6 | 소거리 이동 | 목표 1000 µm, 속도 1000 µm/s 절대 이동 → 위치가 목표 ±1 step 도달, `TargetReached` |
| 1-7 | 방향·단위 확인 | +이동이 기대 방향인지, 1회전(리드만큼) 이동 시 축이 정확히 1회전(마킹 확인) |
| 1-8 | 속도·가감속 | 속도 3단계(1k/5k/20k µm/s) 로 이동 시간 측정 → 이론값 ±10 % |
| 1-9 | 정지 | 이동 중 Halt → 감속 정지 후 `OperationEnabled` 유지 / Quick Stop → 정지 후 서보 오프 |
| 1-10 | 조그 | 누름 중 이동, 뗀 즉시 감속 정지, 버튼 밖에서 떼어도 정지 |
| 1-11 | 원점복귀 | 6098h 방식대로 동작, 완료 후 `HomingAttained`, 위치 0 |
| 1-12 | 알람 | 소프트리밋 넘기기 또는 리밋 센서 입력 → Fault 표시, 알람 리셋으로 복구 |
| 1-13 | 드라이브 설정 쓰기 | 리드·속도 변경 → 다음 명령에 반영. 전자기어 변경 → Configuration 후 반영, NV 저장 후 재기동 시 유지 |

기록: 각 항목의 로그, 상태바 최대 지터·WKC 오류, MEXE02 캡처.

## 2단계 · 벤치, 다축 + IO

**목적**: 축 번호 매핑, 동시 동작, IO·인터록 실동작을 확인한다.

| 항목 | 통과 기준 |
|---|---|
| 슬레이브 분류 | 로그에 드라이브=축, EL1889/EL2889=IO 모듈, EK1100=무시. 축 번호가 물리 순서와 일치 |
| 별칭 매핑 | devices.json/appsettings 별칭이 GUI 축 표·IO 탭에 표시 |
| 동시 이동 | 전체 축 동시 절대 이동 → 모두 도달, 지터·WKC 오류 증가 없음 |
| 개별 정지 | 한 축만 Halt/QuickStop, 다른 축 영향 없음 |
| IO 입력 | 실제 스위치로 각 입력 비트 토글 → IO 탭 LED 와 API 값 일치, 반응 2사이클 이내 |
| IO 출력 | 각 출력 비트 토글 → 램프/릴레이 동작, 상태 출력(RunLamp 등) 조건과 일치 |
| 인터록 (실기) | 비상정지 스위치로 QuickStop, 도어 스위치로 Halt + 차단, 에어리어 센서로 지정 축만 Halt |
| 인터록 해제 | 스위치 복귀 후 서보 온·이동 재개 가능, 트리거 횟수 정확 |
| 시리얼 연동 | RS-232 로 STOP/MOVE 문자열 수신 → 브리지 동작 |
| 재연결 | 해제 → 연결 반복 20회, 매번 OP 도달 |

## 3단계 · 장기 안정성 (72시간 이상)

**목적**: 메모리 누수, 지터 누적, 통신 오류율, 시간 관련 결함을 잡는다.

- 시나리오: 스크립트로 전체 축을 왕복 이동(예: 0 ↔ 50 mm) 반복, 매 10분 상태 출력·IO 토글, 1시간마다 `GET /api/system/status` 를 로그로 저장.
- 관찰 지표: `maxJitterUs`, `missedCycles`, `wkcErrors`, `cyclesPerSecond`, 프로세스 메모리(Working Set), 드라이브 온도·알람.

| 통과 기준 | 값 |
|---|---|
| WKC 오류율 | 0.01 % 미만 (2 ms 주기 72시간 = 1.3억 사이클 중 13,000 회 미만), 연속 오류로 인한 오프라인 0회 |
| 놓친 사이클 | Windows: 총 사이클의 0.1 % 미만 / Linux RT: 0.001 % 미만 |
| 최대 지터 | Windows: 사이클의 50 % 미만 / Linux RT: 100 µs 미만 |
| 메모리 | 72시간 동안 Working Set 증가 10 MB 미만 (누수 없음) |
| 위치 재현성 | 왕복 종료 위치 편차 ±1 step |
| 알람·크래시 | 0회 |

## 4단계 · 고장 주입

**목적**: 비정상 상황에서 안전 측으로 동작하는지 확인한다. 모터 무부하 또는 저속으로 실시.

| 주입 | 기대 동작 |
|---|---|
| 이동 중 EtherCAT 케이블 분리 | WKC 오류 → 10사이클 후 축 오프라인 표시, 인터록 모듈 오프라인 = 활성(안전 측), 드라이브 자체 통신 알람으로 정지 |
| 케이블 재연결 | 감시 스레드가 슬레이브 복구, OP 복귀, 알람 리셋 후 재사용 가능 |
| 중간 슬레이브 전원 차단 | 뒤쪽 슬레이브 오프라인, 앞쪽은 유지. 복전 후 복구 |
| 서보 온 상태에서 API 프로세스 강제 종료 | 드라이브가 PDO 워치독으로 정지(SM 워치독 기본 100 ms 확인) |
| 잘못된 명령 폭주 | 초당 100회 이동 명령 → 마지막 명령만 적용, 지터 영향 없음, 예외 없음 |
| 인터록 활성 중 모든 명령 | 서보온·이동·조그·원점 거부(409), 정지·서보오프·알람리셋은 허용 |
| 설정 오류 | 없는 NIC, 없는 슬레이브, PDO 재매핑 거부 → 명확한 오류 로그로 시작 실패, 무한 재시도 없음 |
| 시리얼 케이블 분리/노이즈 | 브리지가 예외 없이 무시, 재연결 후 수신 재개 |

## 5단계 · 배포 환경 (Linux 미니PC)

**목적**: 운용 환경에서의 실시간 성능과 서비스 운영을 확인한다.

| 항목 | 통과 기준 |
|---|---|
| RT 커널·코어 격리 | `uname -a` 에 PREEMPT_RT, `cat /sys/devices/system/cpu/isolated` 에 지정 코어 |
| 권한 | root 없이 systemd 서비스로 기동, `CAP_NET_RAW`/`CAP_SYS_NICE` 적용, SCHED_FIFO 설정 실패 경고 없음 |
| 부팅 자동 시작 | 전원 재투입 후 60초 내 OP 도달, `/api/system/health` 200 |
| 지터 | 1시간 측정 최대 지터 100 µs 미만, 이후 사이클 1 ms 로 낮춰 재측정 |
| 3단계 반복 | 72시간 장기 시험을 Linux 에서 다시 통과 |
| 외부 연동 | 상위 시스템에서 REST 호출 100만 회 이상, 오류 응답 0 (409/404 는 의도된 경우 제외) |
| 로그·복구 | `journalctl` 에 로그 보존, 서비스 크래시 시 3초 내 자동 재시작(`Restart=on-failure`) |

## 공통 기록 양식

각 시험은 아래를 남긴다.

- 일시, 소프트웨어 커밋/빌드 번호, 드라이브 펌웨어, MEXE02 설정 백업
- 시작·종료 시 `GET /api/system/status` 전체 JSON
- GUI 로그 패널 저장 (또는 `journalctl -u ecatmaster`)
- 통과/실패와 실패 시 재현 절차

## 통과 후 현장 적용 시 주의

- 처음에는 속도·가감속을 운용값의 30 % 로 낮추고 비상정지 인터록이 실제로 동작하는지 먼저 확인한다.
- 소프트리밋(607Dh)과 원점 방식(6098h)을 드라이브에 설정하고 NV 저장했는지 확인한다.
- 인터록·상태출력 규칙은 현장 배선에 맞게 다시 검토한다 (NC/NO, negative/positive switching).
